# 学习方式与文档约定

[返回总导航](../README.md)

## 核心约定

**要求学习成果之前，必须先告诉学习者从哪里学、读哪一部分、按什么顺序学。**

学习任务采用固定链路：

```text
目标与前置 → 学习材料 → 指定阅读范围 → 带问题理解 → 小练习 → 成果 → 验收
```

不能只写“理解框架后画流程图”，应写成“先读某文档的指定章节，回答输入、规则、执行、输出四个问题，再画出对应流程”。

## 每次任务必须具备的字段

| 字段 | 必须说明 |
|---|---|
| 目标与前置 | 本次理解什么；缺少概念时先在哪补 |
| 学习入口 | 可点击的本地资料或核验过的外部来源 |
| 阅读范围 | 精确到章节、示例或函数；同时说明哪些跳过 |
| 顺序与时间 | 先后顺序、必读 / 选读，建议用时而非硬性截止 |
| 阅读问题 | 每份材料带着 1–3 个问题看 |
| 练习与产出 | 读完做什么，成果写到哪个文件 |
| 验收与卡点 | 怎样知道理解了；不懂时退回哪里，不靠扩大阅读量解决 |

## 材料选择原则

- 优先本地版本的中文教程与最小示例，其次是相关算子说明，最后才是源码。
- 先用容易理解的文本示例建立框架直觉，再迁移到图像，不强求第一步就多模态。
- demo 目录是导航，不自动等于教材；项目 README 是总览，不要求整篇通读。
- 概念阅读不等于运行：明确“只读，不执行”，避免无谓安装和模型下载。
- 文档、注释和代码不一致时明确指出，不能让学习者靠错误注释建立概念。
- 单次优先 1–3 份必读材料，其他放后续；不知道出处时先查证，不编造路径。

## 分工与状态

助手负责准备学习路线、讲解必要概念、检查证据；学习者负责复述理解、尝试实验并记录疑问。助手不能替学习者宣称学会。

后续阶段只搭结构时，标注“学习路线待补，暂不作为执行任务”；进入该阶段前补齐材料。约定适用于本项目未来新增和更新的所有学习规划文档。
