## 1. 总体策略

```
主攻线 A  多模态数据生产（Data-Juicer + 自建分布式 pipeline）   ← 决定能否进岗位
主攻线 B  多模态/VLM 原理补全（看懂用到的模型，不陷入训练）     ← 面试兜底
业务线 C  vlm-triage 落地（业务认知 + 简历场景素材）             ← 够用即可，勿深挖单机细节
辅线   D  Lakehouse 底座（复用现优势，降级为维持投入）          ← 就业安全网
```

> ⚠️ 关键认知：**vlm-triage 是"应用示例/展示牌"，不是"学习进阶主线"**。它给不了你 Data-Juicer 能给的「大规模 + 可展示 + 分布式」能力。C 线只投少量精力，A 线才是训练场。

### 每周时间分配建议

- 主线 A：约 45–50%
- 主线 B：约 20%
- 业务线 C：约 15%（在职工作里顺手完成）
- 辅线 D：约 15–20%

## 3. 阶段明细

### 阶段 0：方向对齐 + 概念地图 + 工具并行冒烟（第 1 周）

目标：方向定清楚，**先建"概念地图"，不是学完概念再动手**——vlm-triage 建链路、Data-Juicer 冒烟、六问概念三件事**并行开**，别严格串行。

- [ ] **六个概念问题建地图**（能用自己的话解释 + 能对照项目指出对应位置即达标，**别先补 DL 课程**）：
  1. **生产什么数据？** 图文对/视频-描述/交错图文/指令问答是什么；预训练 vs 指令微调的数据目标差异。
  2. **怎样的数据算好？** 有效性/相关性/多样性/重复/污染/授权分别意味着什么。
  3. **模型在生产链路做什么？** 特征提取/相关性评分/自动标注/描述生成是不同任务，别混为一谈。
  4. **如何判断加工有效？** 数据质量指标 vs 下游训练效果要分开验证。
  5. **怎样组织数据？** 媒体文件/样本 ID/元数据/处理版本/数据集清单如何关联。
  6. **计算瓶颈在哪？** 下载/解码/CPU 预处理/GPU 推理/输出存储各有什么开销。
- [ ] **Data-Juicer / img2dataset / WebDataset 冒烟并行开**：跑通一个最小样例（工具会反向帮你把概念讲清）。
- [ ] **vlm-triage 只用于建地图 + 业务素材**：梳理一条端到端链路（抽帧→embedding→相似度→定位）并画出流程图。
- [ ] 读一遍目标岗位 JD，映射到「已有/待补/迁移即可」，产出差距表（用第 0 节表）。

#### vlm-triage「停」判据（学到能讲清 4 点就封存）

1. 它端到端要解决的业务问题是什么；
2. 抽帧→embedding→相似度→定位，每步的输入输出与解决的问题；
3. 数据如何组织（媒体文件/样本 ID/元数据/结果如何关联）；
4. **它没解决/不适用在哪**（能讲边界 = 显得你真懂）。

> **别碰**：内部某个 filter 的具体实现、微调训练细节、prompt 调优。到不了 3 分钟讲清 4 点，就直接去 Data-Juicer，别再补。

### 阶段 1：Data-Juicer 主攻，建立「多模态数据生产」手感（第 2–5 周）—— 主线 A

目标：把「结构化表 ETL」心智迁移到「图像/视频生产」。**这是主训练场**：概念想不起就回查第 0 节六问，别停下手；vlm-triage 到此封存（要业务素材就回来引用你第 0 周画的图，别再投入）。

- [ ] **img2dataset**（第 2 周）：URL → 下载缩放 → 打包成 webdataset；理解断点续传/并行/分辨率过滤。
- [ ] **Data-Juicer**（第 3–4 周）：跑「图像/视频 → 去重 + 清晰度/质量过滤 → 干净子集 + 质量报告」，理解算子化 + 可配置 pipeline。
- [ ] 记录每步的「数仓类比」：采集=？清洗=？入库=？质量=？血缘=？（这是你面试讲"迁移能力"的素材）。
- [ ] 里程碑：能不看文档跑通 Data-Juicer 一条算子链路，并解释每个算子作用。

### 阶段 2：自建「多模态数据生产 pipeline」作品（第 6–10 周）—— 主线 A 核心

目标：产出一个**可复现、可对外展示**的端到端作品（这是简历主弹）。

- 建议主题：**「仿真/图像多模态数据的生产 + 清洗 + 表征 + 可检索交付」pipeline**
  - 借鉴 vlm-triage 的「抽帧 + embedding」思路；
  - 落到 Data-Juicer 算子 + Spark 做分布式规模化；
  - 加入**数据质量监控 / 血缘 / 版本管理 / schema（图+元数据+向量如何组织）**——这是你的治理差异点。
- [ ] 第 6–7 周：设计 schema 与架构（输入什么、清洗什么、输出存储什么）。
- [ ] 第 8 周：接入 Ray/Spark 做分布式（补 Ray 缺口）。
- [ ] 第 9 周：补质量监控/血缘/版本控制。
- [ ] 第 10 周：打磨成一个能 demo 的仓库 + README + 效果截图。
- 里程碑：**能向面试官完整演示并讲清这条 pipeline**，含规模、痛点、你的设计取舍。

### 阶段 3：补面试技术广度（第 11–13 周）—— 主线 B

目标：面试问不倒，兜底。

- [ ] **VLM / embedding 原理**：CLIP 对比学习为何有效、视觉编码器（ViT/CNN）、embedding 语义、相似度度量、图像去重打分。
- [ ] **Ray**：理解分布式任务调度、数据并行、MapReduce 式处理大图/大视频。
- [ ] **vLLM / 推理加速**：看懂你环境里的 vllm-serve-* 即可（对应 JD「推理加速优先」加分项）。
- [ ] **理解层即可，不做训练/微调**（那是算法岗的事，别陷进去）。

### 阶段 4：作品化 + 简历 + 投递（第 14–16 周）

目标：收口成可投递状态。

- [ ] 简历主线重写为：「数仓/治理底座 + 多模态数据管线」，强调**迁移能力**而非"学了新框架"。
- [ ] 准备 1 个可深挖主故事 = 阶段 2 的 pipeline 作品；1 个辅故事 = vlm-triage 参与经历。
- [ ] 用「可视化能力地图 + 每周打卡」做复盘（见第 5 节）。
- [ ] 模拟面试 2–3 次（重点：讲清多模态数据全流程 + 治理迁移）。
- [ ] 第 16 周开始投递。

## 7. 常见坑提醒

- ⚠️ 别陷进纯模型数据合成（要算力 + 模型调参），那是算法岗的事。
- ⚠️ 别拿 vlm-triage 当进阶主线深挖，它是展示牌不是训练场。**学到"能讲清抽帧/embedding/相似度/定位四步的输入输出 + 它的不适用边界"就封存**，别追内部 filter 实现和微调细节。
- ⚠️ 别被"先做扎实 Lakehouse 再转型"带偏成串行——底座用现优势维持即可。
- ✅ 你的差异化护城河 = **数据治理底座 + 迁移到多模态数据**，面试多讲这个。
