# 学习文档维护约定

适用范围：本目录及其子目录。新增或修改学习计划、阶段说明、学习任务和模板时必须遵守。

## 路径一律加可点击链接

在文档中引用本地文件、目录、配置、输出或源码时，一律写成可点击的相对链接 `[显示名](相对路径)`，不写裸文本路径。相对路径以当前文档所在目录为基准。

例外：代码块（```text``` 等）内的命令行文本是「实际敲的命令」，不支持链接渲染，保持原样；如需引用该命令涉及的配置文件，在代码块外用一行「配置文件位置：[配置 A](...) · [配置 B](...)」补充。

## 先提供学习路径，再要求产出

用户具备数仓经验，但尚在建立多模态宏观认知。不得默认用户知道去哪里学，也不得只列“画图、跑通、读源码、写总结”等成果要求。

每个可执行学习任务必须提供：
1. 学习目标与必要前置知识。
2. 具体学习入口：优先已核对的本地中文文档；提供可点击路径，不只写项目名。
3. 阅读范围：读哪些章节、示例或函数，哪些内容暂时跳过。
4. 学习顺序与建议时间：区分必读、选读、后续；初次任务优先 1–3 份材料。
5. 带着什么问题阅读，以及怎样从材料过渡到小练习。
6. 对应成果及验收标准：材料应足以支持任务；未讲解的能力不得直接作为验收要求。
7. 卡点处理：缺材料时由助手补导读或解释，不让用户自行补完整课程。

后续阶段可以只保留目录与目标，但必须标注“学习路线待补，暂不作为执行任务”。进入该阶段前先补齐上述信息。不要为填满文档而猜测资料内容或编造实验结果。

更新时同步检查总导航、阶段 README、学习笔记和计划中的开始动作，避免一处要求先学习、另一处仍要求直接交成果。保留用户已写笔记，不代替用户填写个人理解或宣称已学会。

持久化约定见 `00-学习规划/学习方式与文档约定.md`；当前具体阅读路线放在阶段笔记中，其他文件链接引用，避免重复维护。
