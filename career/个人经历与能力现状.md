## 1. 记录边界

以下是私人职业记录的概括，不是完整简历，也不是独立核验结果。已移除可识别身份的信息、雇佣与收入细节、求职进度、公司项目指标和内部链接。

## 2. 能力基础与待补项

| 方向 | 当前记录与边界 |
|---|---|
| 数据仓库与数据工程 | 具备结构化数据处理、SQL 开发及数据治理经验 |
| 工程方案 | 有增量处理、性能与成本问题定位方面的经验；具体成果需另行提供经授权的证据 |
| Python | 能处理常见算法与简单逻辑；复杂工程代码、继承与跨方法调用仍需加强 |
| 实时处理 | 需继续补充实时计算理论、实践与排错能力，不把接触过工具等同于熟练掌握 |
| 平台研发 | 不将数据开发经验直接等同于数据平台研发经历 |
| 多模态 | 当前以个人学习与实验为主，不宣称已有多模态生产交付经验 |
| AI 辅助研发 | 需区分本人设计与编码、AI 辅助、团队成果和独立可复现的能力 |

## 3. 可以继续积累的证据

- 数据处理方案：说明需求、输入输出、增量语义、质量检查与异常处理。
- 性能优化：使用可公开或合成数据，固定工作量与计时口径，对比资源和结果。
- 质量治理：解释规则、告警、验收与追溯，不披露内部表名、规模及业务指标。
- AI 辅助：说明辅助范围、人工核验步骤、失败案例和本人贡献。
- 个人作品：提供有权公开的代码、测试、运行说明与局限，不复用未获授权的公司材料。

以上是证据整理方向，不代表这些公开作品已经完成。

## 4. 多模态学习

当前进度以[学习导航](../learning/README.md)为准，不在职业档案中复制可能过期的阶段状态。

学习重点包括数据预处理、质量校验、异常处理、框架调用链、表征与性能测量。阅读源码、助手代跑、纸上练习与本人独立实现应分别标注。

## 5. 后续自查

1. 能否独立解释、修改并测试一个小模块？
2. 实时计算缺口属于理论、实践、排错还是系统设计？
3. 优化结果是否有固定口径、对照条件与正确性证据？
4. 作品是否使用了有权公开的数据和代码？
5. 面试表述是否准确区分个人贡献、团队成果和学习实验？

私人职业条件和未授权的项目证明材料不纳入公开仓库。
