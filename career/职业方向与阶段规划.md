# 职业方向与阶段规划（脱敏版）

[返回入口](README.md) · [能力现状](个人经历与能力现状.md)

## 1. 方向与边界

以结构化数据工程为基础，用 AI 辅助改进研发与验证流程，通过多模态数据工程拓展能力。实时计算与湖仓知识按实际需求补充，不同时铺开多条重型学习路线。

这是个人学习取舍，不是市场预测、收入承诺或具体求职计划。

## 2. 精力安排

- 主线：多模态数据处理及所需的 Python 工程实践，围绕一条处理链学习。
- 辅线：巩固已有数据工程能力，按实际岗位要求补充短板。
- 暂缓：完整平台建设、多套分布式技术栈、与当前作品无关的工具堆叠。
- 新任务应替换低优先级任务，而不是无限增加学习负担。

## 3. 阶段安排

### 第一阶段：形成可解释的小作品

按[现有学习路线](../learning/README.md)补充小范围修改、测试、排错和结果核对。遵守[学习约定](../learning/00-学习规划/学习方式与文档约定.md)：先提供材料、范围与导读，再要求练习和产出。

### 第二阶段：形成可复现证据

整理运行说明、输入输出、测试、失败案例与限制。用模拟问答核实理解，不将阅读完成直接写成独立开发能力。

### 第三阶段：按反馈调整

结合公开岗位要求和技术交流反馈识别共性缺口。记录下一步改进，不在公开资料中保存联系人、面试进度、报价或个人时间安排。

以上是学习阶段，不是带有承诺日期的求职计划。

## 4. AI 与数据工程的练习范围

可以用合成或公开数据练习：资料检索 → 口径解释 → 处理建议 → 人工核验。

关注固定评测问题、对照条件、答案依据、失败案例与人工成本。检索指标不等于业务正确率；个人原型不等于上线平台。

不接入未经授权的生产系统，不复制公司数据或内部知识库，不自动修改生产任务。

## 5. 多模态工程能力目标

1. 解释数据规则及其消费者需求。
2. 修改一个算子或模块，补齐正常、边界与异常测试。
3. 使用日志或调试器说明调用链并定位问题。
4. 有条件时接入模型步骤，核对产物与失败情况。
5. 在固定工作量与结果一致的前提下测量吞吐、资源和成本。

这些是待持续积累的目标，不代表已经具备全部能力。个人实验不能包装为公司生产成果。

## 6. 定期复盘

- 新增了什么可核验的事实？
- 哪些由本人完成，哪些依赖 AI 或他人？
- 对照与测试发现了什么失败或限制？
- 是否更能读、改、测、排错，而不只是看过更多资料？
- 下一周期只保留哪一到两个重点，明确暂不做什么？

无新增证据时不因焦虑反复换方向；有新证据时允许调整。
