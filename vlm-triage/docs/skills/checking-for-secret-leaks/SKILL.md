# Skill: Checking and Preventing Secret Leaks

Prevent accidental exposure of secrets, credentials, and sensitive information in the codebase. This skill provides guidance on properly storing secrets and verifying they're not leaked in commits or configuration files.

## Overview

The repository follows a layered approach to managing secrets:

- **Public Configuration** - Committed to repo, suitable for team-level settings
- **Local Configuration** - Never committed, for personal and sensitive settings
- **Templates** - Committed templates with placeholder values
- **Environment Variables** - Runtime-injected secrets

## Key Principles

1. **Personal accounts must be removed** - Never commit personal credentials
2. **High-cost resources protected** - Hadoop, LLM API keys must be kept secret
3. **Team keys can be committed** - Low-sensitivity team identifiers, URLs
4. **Local.sh is gitignored** - Stores individual developer secrets
5. **Pre-pixi.sh generates templates** - Provides safe templates with placeholders

## Secret Categories

### 1. Personal Credentials (REMOVE from repo)

**Examples**:
- Personal usernames: `<your-username>`
- Personal API keys/tokens
- Personal SSH keys
- Personal database passwords

**Action**: Remove immediately if found

**Check in recent commits**:
```bash
# Search for personal usernames
git log -p -S "<your-username>" --oneline | head -20

# Search for common personal patterns
git log -p | grep -i "username.*<your-username>\|password.*[a-z]" | head -20
```

### 2. High-Cost Resource Credentials (PROTECT)

**Examples**:
- Hadoop credentials (`HADOOP_USER_NAME`, `HADOOP_USER_PASSWORD`)
- LLM API keys (OpenAI, Claude, etc.)
- GPU cluster credentials
- Database passwords for production systems
- Voyager platform credentials

**Storage Location**: `scripts/activation/local.sh` (gitignored)

**Template Location**: `scripts/activation/pre-pixi.sh` (committed with placeholders)

**Example - Local.sh (never committed)**:
```sh
export HADOOP_USER_NAME="actual_username"
export HADOOP_USER_PASSWORD="REDACTED"
export OPENAI_API_KEY="REDACTED"
```

**Example - Pre-pixi.sh template (committed)**:
```sh
export HADOOP_USER_NAME="HADOOP_USER_NAME"  # Placeholder
export HADOOP_USER_PASSWORD="REDACTED"  # Placeholder
export OPENAI_API_KEY="REDACTED"  # Placeholder with instructions
```

### 3. Team-Level Configuration (Can commit)

**Examples**:
- Project endpoints: `TRIAGE_CV_API_URL`, `TRIAGE_EMBEDDING_API_URL`
- Team usernames: `COOPER_USERNAME`
- Build parameters: `TRIAGE_LOCATOR_TASK_LIMIT`
- Public API URLs

**Storage**: Can be in `local.sh` or environment variables

**Example**:
```sh
export TRIAGE_CV_API_URL="http://localhost:8000"
export TRIAGE_EMBEDDING_API_URL="http://localhost:8001"
export COOPER_USERNAME="team_account"  # Team account, not personal
```

- Use uppercase variable names
- Group by category with `## category ##` comments
- Add descriptive comments
- Use meaningful placeholder values

## Checking for Secret Leaks

### 1. Search for Personal Usernames

```bash
# Check recent commits for personal username
git log -p --all | grep -i "<your-username>" | head -20

# Check working directory
grep -r "<your-username>" apps/ lib/ --include="*.py" --include="*.toml" --include="*.yml"
```

### 2. Search for Uncommented Secrets

```bash
# Find uncommented exports with actual values (not PLACEHOLDERS)
grep -r "^export.*=" scripts/activation/local.sh | grep -v "PLACEHOLDER\|your-\|replace"

# Find patterns that look like keys
grep -r "^[A-Z_]*_KEY\s*=" . --include="*.sh" --include="*.py" --include="*.toml" | grep -v "#"
grep -r "^[A-Z_]*_PASSWORD\s*=" . --include="*.sh" --include="*.py" --include="*.toml" | grep -v "#"
```

### 3. Check Committed Local Files

```bash
# Verify local.sh is gitignored
git check-ignore scripts/activation/local.sh && echo "✓ Properly gitignored"

# Search for any committed secrets in local.sh history
git log --all -p -- scripts/activation/local.sh | grep -i "password\|api.key\|secret" | head -10
```

### 4. Search for High-Cost Resource Credentials

```bash
# Look for Hadoop credentials with real values
git log -p --all | grep -B2 -A2 "HADOOP_USER_PASSWORD" | grep -v "^--$" | head -20

# Look for API keys pattern
git log -p --all | grep -E "api.?key|openai|claude" -i | head -20

# Look for database passwords
git log -p --all | grep -E "password.*=|db.*password" -i | head -20
```

### 5. Automated Secret Scanning

**Using git-secrets** (if available):
```bash
# Install (once)
brew install git-secrets

# Configure patterns
git secrets --register-aws
git secrets --add 'HADOOP_USER_PASSWORD'
git secrets --add 'OPENAI_API_KEY'

# Scan current commits
git secrets --scan
```

**Manual verification script**:
```bash
#!/bin/bash
# Check for secret patterns in Python files
python_files=$(find . -name "*.py" -not -path "./.*" -not -path "./.git/*")

echo "Checking for secret patterns..."
for pattern in "api.key" "password.*=" "secret.*=" "token.*=" "HADOOP"; do
    found=$(grep -r "$pattern" $python_files 2>/dev/null | grep -v "^#\|PLACEHOLDER" | wc -l)
    if [ $found -gt 0 ]; then
        echo "⚠️ Found $found potential secrets matching '$pattern'"
        grep -r "$pattern" $python_files 2>/dev/null | grep -v "^#\|PLACEHOLDER"
    fi
done
```

## Fixing Secret Leaks

### 1. If Personal Credentials Found in Working Directory

**Action**: Remove immediately
```bash
# Remove from working files
# (edit file manually)

# Verify removal
git diff scripts/activation/local.sh | grep "^+.*[a-z]" | grep -v "PLACEHOLDER"
```

### 2. If Personal Credentials Committed to Git

**Action**: Rewrite history (if not pushed to main branch)

```bash
# Check if pushed
git log origin/main..HEAD --oneline | grep "your commit"

# If not pushed, amend or rebase
git rebase -i HEAD~5  # Adjust count as needed

# Or if already pushed, create a fix commit
git commit -m "security: remove personal credentials

Remove personal username and API keys that were
accidentally committed in previous commits."
```

### 3. If Secrets Pushed to Shared Branch

**Urgent action required**:
1. Create new credentials (invalidate old ones)
2. Create fix commit removing secrets
3. Notify team to pull latest
4. Document incident

```bash
# Create a new commit removing secrets
git commit -m "security: remove leaked credentials

⚠️ URGENT: Previous commits contained exposed credentials.
Affected credentials must be regenerated.

- Invalidated HADOOP_USER_PASSWORD
- Regenerated OPENAI_API_KEY
- Removed personal username references

Team members: pull latest and reset local environment."
```

## Checklist for New Commits

Before committing, verify:

- [ ] No personal usernames or account names
- [ ] No API keys or tokens (should be in local.sh, not code)
- [ ] No database passwords
- [ ] No Hadoop/GPU cluster credentials
- [ ] All `.sh` files have template format (PLACEHOLDER values)
- [ ] `.gitignore` includes `scripts/activation/local.sh`
- [ ] New secrets added to both `local.sh` and `pre-pixi.sh`

**Quick check**:
```bash
git diff --cached | grep -E "password|api.?key|secret|token" | grep -v "PLACEHOLDER"
```
