### Iteration 20260513.001 — Embedding API 测试分层规划

**议题：** `apps/embedding_api/test.py` 按测试方法论分层重构的设计方案

**规划结论：**

1. **测试分层（4 层）：**
   - `[smoke]` — 冒烟测试：最快路径验证 API 通断（单模型单图，1-2 条用例）
   - `[functional]` — 功能测试：各端点正常功能验证（不同模型族、参数组合、输出格式）
   - `[coverage]` — 覆盖测试：边角情况/错误路径/非法输入（空文件、损坏图片、不存在的 model_id、超大文件、响应内容正确性验证）
   - `[stress]` — 压力测试：并发/稳定性（多线程并发、混合端点压测）

2. **文件布局：** 保持单文件 `apps/embedding_api/test.py`，用 pytest markers 分层，不拆分为多文件
   - 理由：shell-trick shebang 保持统一，测试量适中（~20 个），pytest markers 原生支持分层选择

3. **命名规范：** `test__<层级>__<端点>__<场景>` 三段式命名，便于 `-k` 过滤

4. **注册 markers：** 需在 `pyproject.toml` 的 `[tool.pytest.ini_options]` 中注册 `smoke` / `functional` / `coverage` / `stress` 四个 marker

5. **扩展点：**
   - 功能测试增加对不同 `fmt`（arrow_tensor/arrow_recordbatch/safetensors/parquet）的逐格式验证
   - 覆盖测试增加响应内容 shape/dtype 正确性断言（不满足于 status_code）
   - 错误路径测试验证合理的 HTTP 状态码和错误消息

### 9. 文件布局方案

```
interface variant 够简单  → doctest (>>>)
          ↓ 不够简单
interface variant 能自检  → 内联 smoke (if __name__)
          ↓ 自检太重
外部依赖多 / 需参数化   → tests/ functional/coverage/stress
```

### 放置规则

| 测试类别 | 位置 | 标记 | 数 N |
|----------|------|------|------|
| **docstring 示例** | 函数体内 `>>>` | pytest --doctest-modules | ~函数数 |
| **内联 smoke** | 模块底部 `if __name__` | conftest 按函数名自动标 smoke | ~variant / overload 数 |
| **functional + coverage** | `tests/**/` | @pytest.mark.functional / .coverage | 无上限 |
| **stress** | `tests/**/` | @pytest.mark.stress | 按需 |

### 自动标记（conftest 计划）

```python
def pytest_collection_modifyitems(config, items):
    for item in items:
        # 内联文件 (非 tests/ 下的 test_ 函数) → auto smoke
        if "tests/" not in str(item.fspath) and item.name.startswith("test_"):
            item.add_marker(pytest.mark.smoke)
```
