## 概述

建立分层缓存系统，覆盖高成本接口结果缓存、tool/resource 缓存，跨 session 共享，减少重复计算和 I/O。

## 背景

LLM 调用、模型推理、外部 API 请求等高耗时操作缺乏缓存，重复请求浪费算力和时间。Resource 对象的存储转换也未充分利用缓存加速。

## 范围

**在范围内：**

- L1 内存缓存（LRU，session 级）+ L2 持久化缓存（SQLite/Redis，跨 session）
- 缓存键确定性生成（内容哈希、参数哈希）
- TTL、LRU 过期策略
- 并发安全
- 缓存统计（命中率、大小）

**不在范围内：**

- 不涉及模型推理结果格式的变更
- 不替代 ResourceRepository 已有的 LRU 机制

- 作为系统用户，我希望重复的计算和 I/O 操作能被缓存，减少相同数据的重复处理时间
- 作为系统管理员，我希望缓存策略能够提高并发场景下的整体性能，同时保证数据一致性
- 作为开发者，我希望缓存系统能够无感地集成到 agent、service、resource 层，避免重复实现缓存逻辑

## 需求详情

### 功能需求

1. **高成本接口结果缓存** - 对 LLM 调用、模型推理、外部 API 请求等高耗时操作进行结果缓存，减少重复计算

2. **Tool/Resource 缓存** - 缓存 tool 的输入输出、资源对象，支持多模态数据占位符通过 name 访问，对 agent 层无感

3. **跨 Session 缓存** - 不同作业/session 如果使用相同数据，通过缓存加速访问，减少重复处理

4. **Resource 存储源自动转换** - Resource 对象自动适配不同存储源（本地文件、HTTP、S3 等），缓存感知存储转换

### 技术需求

1. **缓存分层** - 区分内存缓存（快速）和持久化缓存（共享），支持多层缓存策略

2. **缓存过期策略** - 支持 TTL、LRU、显式失效等多种过期机制

3. **缓存键生成** - 确定性的缓存键生成，支持内容哈希、参数哈希等方式

4. **并发安全** - 缓存操作在高并发场景下无竞态条件

5. **缓存统计** - 记录缓存命中率、大小、过期情况，便于监控和优化

## 设计方案

### 架构设计

#### 1. 缓存分层

```
┌─────────────────────────────────────────┐
│ L1: Memory Cache (内存缓存)              │
│ • 快速访问，session 级隔离               │
│ • LRU 过期策略                          │
└─────────────────────────────────────────┘
                ↓
┌─────────────────────────────────────────┐
│ L2: Persistent Cache (持久化缓存)        │
│ • 跨 session 共享                       │
│ • SQLite/Redis 存储                     │
│ • TTL 过期策略                          │
└─────────────────────────────────────────┘
                ↓
┌─────────────────────────────────────────┐
│ L3: Resource Storage (资源存储)          │
│ • 多源存储（本地、HTTP、S3）            │
│ • 自动转换、懒加载                      │
└─────────────────────────────────────────┘
```

#### 2. 缓存应用场景

| 场景 | 缓存层 | 过期策略 | 共享范围 | 优先级 |
|------|-------|--------|---------|-------|
| LLM 调用结果 | L2 | TTL (24h) | 跨 session | High |
| 模型推理结果 | L2 | TTL (7d) | 跨 session | High |
| Embedding 向量 | L2 | TTL (30d) | 跨 session | High |
| Resource 对象 | L1 + L2 | LRU + TTL | session 隔离 + 共享 | Medium |
| Tool 输出 | L1 | LRU | session 级 | Medium |
| 外部 API 响应 | L2 | TTL | 跨 session | Medium |

### 实现步骤

#### Phase 1: 基础缓存框架 (Week 1-2)

1. **定义缓存接口**
   - `Cache` 基类：get/set/delete/clear/stats
   - `MemoryCache`：LRU 实现，session 级隔离
   - `PersistentCache`：SQLite 后端，支持 TTL

2. **缓存键生成**
   - 确定性键生成：`hash(operation, args, kwargs)`
   - 支持自定义 key 函数

3. **缓存装饰器**
   - `@cache_result(ttl=3600)` - 自动缓存函数结果
   - `@cache_key(fn)` - 自定义缓存键生成

#### Phase 2: Service 层集成 (Week 2-3)

1. **LLM 调用缓存**
   - 在 `lib/utils/llm_utils.py` 集成缓存
   - 缓存 OpenAI API 响应 (gpt-4, gpt-4-vision 等)
   - 缓存键包含：模型、prompt、temperature

2. **模型推理缓存**
   - 在 `EmbeddingService` 添加向量缓存
   - 在 `CvService` 添加相似度计算缓存
   - 缓存键包含：模型、输入 ID、参数

3. **Resource 对象缓存**
   - 在 `ResourceRepository` 集成缓存
   - 缓存 Image、Video、Table 对象
   - Session 级隔离 + 持久化共享

#### Phase 3: Agent 系统集成 (Week 3-4)

1. **Tool 输出缓存**
   - 在 `pydantic_ai` 工具层添加缓存
   - 缓存 tool 函数的返回值
   - 透明集成，对 agent 无感

2. **Resource 缓存**
   - Resource 加载时自动缓存
   - 支持多源存储自动转换
   - 缓存过期后自动重新加载

#### Phase 4: 优化与监控 (Week 4)

1. **缓存策略优化**
   - 监控缓存命中率
   - 动态调整 TTL 和 LRU 策略
   - 缓存预热机制

2. **缓存统计**
   - 记录缓存大小、命中率、过期情况
   - 集成 logfire 监控

3. **缓存管理界面**
   - 提供缓存查看、清理、统计接口
   - FastAPI 端点或管理命令

## 决策记录

- **缓存分层**：选择内存 + 持久化二层架构，平衡性能和共享性
- **持久化存储**：优先使用 SQLite（轻量），后续可选 Redis
- **过期策略**：LLM 和 API 用 TTL，Resource 用 LRU + TTL 组合
- **跨 session 共享**：通过持久化缓存层实现，支持不同作业复用数据

## 注意事项

1. **缓存一致性** - 需要考虑缓存失效机制，确保数据不过期
2. **缓存隔离** - 某些场景需要 session 级隔离，某些场景跨 session 共享，需要清晰设计
3. **缓存大小控制** - 防止缓存无限增长，定期清理或使用配额限制
4. **缓存调试** - 在开发时提供缓存禁用或跳过机制，便于调试
5. **法规合规** - 缓存个人数据或敏感数据时需符合数据保护规范

### 术语表

- **LRU** - Least Recently Used，最近最少使用淘汰策略

- **Resource** - 本项目中的多模态数据抽象（Image, Video, Table）
- **Tool** - pydantic_ai 中的代理工具
- **Session** - 单次作业/请求的执行上下文
